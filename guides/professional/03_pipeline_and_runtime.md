# ⚙️ Module 03: Pipeline Desugaring & Runtime Codegen

This module covers the execution model of TensorLoom, the compilation passes for the functional pipe operator (`|>`), Automatic Mixed Precision (AMP), Kernel Fusion with `torch.compile`, and non-reentrant activation checkpointing.

---

## 1. The Functional Pipe Operator (`|>`) Desugaring

In TensorLoom, expressions can be composed using the pipe operator:

```
let out = x |> self.conv1 |> self.bn1 |> relu |> self.conv2 |> self.bn2
```

### 1.1 AST Representation
The parser treats `|>` as a left-associative binary operator yielding a tree of `PipeExpr` nodes:

```
                PipeExpr
               /        \
          PipeExpr     self.bn2
         /        \
    PipeExpr    self.conv2
   /        \
...         relu
```

### 1.2 Lowering Algorithm
The code generator (`_emit_pipe`) recursively desugars the left-hand side and wraps it into the target callable:

$$\text{Desugar}(E_{\text{left}} \mid> F) \implies F(\text{Desugar}(E_{\text{left}}))$$

```python
def _emit_pipe(self, node: PipeExpr) -> str:
    left_str = self._emit_expr(node.left)
    if isinstance(node.right, Variable):
        # Function or activation like 'relu'
        func_name = node.right.name
        if func_name in ("relu", "gelu", "silu", "sigmoid", "tanh", "softmax"):
            return f"F.{func_name}({left_str})"
        return f"{func_name}({left_str})"
    elif isinstance(node.right, FunctionCall):
        # Parameterized call like 'dropout(p=0.1)'
        args = [left_str] + [self._emit_expr(a) for a in node.right.args]
        return f"{node.right.name}({', '.join(args)})"
```

## 2. Automatic Mixed Precision (AMP) Context Synthesis

When `precision = fp16` or `precision = bf16` is declared in a `train` block, the backend instruments the training step with hardware-accelerated mixed precision:

```python
# Generated by PyTorchBackend._emit_train_block
scaler = GradScaler("cuda")

for batch_idx, (inputs, targets) in enumerate(data):
    inputs, targets = inputs.to(device), targets.to(device)
    optimizer.zero_grad()

    with autocast(device_type='cuda', dtype=torch.float16):
        outputs = net(inputs)
        loss = criterion(outputs, targets)

    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
```

### Technical Benefits:
- Tensor Cores on NVIDIA Volta/Ampere/Hopper GPUs operate at 2x–4x throughput on FP16/BF16 matrices.
- Memory consumption of intermediate activation maps is halved.
- Dynamic loss scaling (`GradScaler`) prevents underflow during backward gradient computation.

## 3. Kernel Fusion via `torch.compile(max-autotune)`

During model instantiation in `.tl` scripts (`let net = Model()`), the backend automatically inserts TorchDynamo graph capture:

```python
net = Net().to(device)
net = torch.compile(net, mode="max-autotune")  # TensorLoom Automatic Kernel Fusion
```

### Compiler Optimization Pipeline:
1. **TorchDynamo**: Intercepts Python frame execution and traces tensor operations into FX Graphs.
2. **TorchInductor**: Generates fused C++/OpenMP code for CPU and custom Triton kernels for GPU, eliminating memory bandwidth bottlenecks caused by intermediate point-wise tensor allocations.

## 4. Non-Reentrant Activation Checkpointing

When `checkpoint = true` is declared in a training block, TensorLoom refactors the model's `forward` method into a split checkpoint graph:

```python
class CheckpointedNet(nn.Module):
    def _forward_body(self, x):
        x = self.layer1(x)
        x = self.layer2(x)
        return x

    def forward(self, x):
        from torch.utils.checkpoint import checkpoint
        return checkpoint(self._forward_body, x, use_reentrant=False)
```

### Memory Complexity Tradeoff:
- Standard Forward: Activation memory scales as $O(L)$ where $L$ is the number of layers.
- Checkpointed Forward: Drops activation memory overhead to $O(\sqrt{L})$ by discarding intermediate activations during the forward pass and recomputing them on-demand during backpropagation.
